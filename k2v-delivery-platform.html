快速验证 · 8 周从 0 到商用

K2V 智能咨询交付平台

面向咨询 / 知识密集型业务的智能化交付平台 · 多引擎协作 Agent + 知识增强 RAG

8 周完成 MVP 并商用 多引擎协作调度 七层 PromptOps 体系 AI + 行业知识商业化验证
背

背景 · Situation

Background

咨询 / 知识密集型业务有一个核心痛点：交付高度依赖资深专家个人经验。专家数量有限、经验不可复制、交付流程难标准化——公司希望把行业专家知识沉淀为可复用的 AI 咨询能力，让"专家一对一"变成"AI + 专家规模化"。

角

我的角色 · Task

My Role

作为产品负责人，组建产研团队，用 MVP 思维在8 周内完成平台从 0 到 1并交付商用。核心目标不是做"大而全"，而是快速验证"AI + 行业知识"的商业化模型是否成立。

决

关键决策 · Action

Key Decisions
Q1为什么用"多引擎协作 Agent"而不是单一大模型？
咨询场景任务差异极大：有的要精准检索、有的要深度推理、有的要快速生成。单一模型"什么都干"必然又贵又不精。我设计了多引擎协作架构——让不同模型各司其职（检索用 A、推理用 B、生成用 C），由编排层按任务类型动态调度，兼顾质量与成本。
Q2怎么让"非技术顾问"也能配置 AI 交付流程？
建立 Prompt 模板库（沉淀七层 PromptOps 体系）+ 效果评估机制：顾问不需要懂 Prompt 工程，只需从模板库选择、按业务填充参数。同时每个交付流程都带效果评估，好不好用数据说话，而不是凭感觉。
Q3专家知识怎么变成 AI 可用的资产？
基于 RAG 知识增强：把行业文档、专家方法论沉淀为知识库，AI 回答问题时"先查资料再作答"，降低幻觉、可追溯来源。（白话：把行业文档变成 AI 可查询的知识库，回答先引用依据，减少胡说八道）

复

复盘 · Retrospective

Lessons
  • 坑 1：MVP 范围守不住。业务方总想加功能，我用"8 周商用"当硬约束，把非核心需求全部排到二期。教训：时间盒是 MVP 最好的朋友。
  • 坑 2：知识库质量决定 AI 上限。文档不清洗就入库，检索效果一塌糊涂。后期补了文档清洗和分块策略，效果才起来——知识工程的重要性被严重低估。
  • 坑 3：多引擎调度黑盒化。早期调度逻辑不透明，出问题难排查。后来加了可观测性设计，每次任务记录"用了哪个模型、为什么"，客户信任度明显提升。
